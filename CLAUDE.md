Skills are organized into bucket folders under `skills/`:

- `engineering/`: daily code work
- `productivity/`: daily non-code workflow tools
- `misc/`: kept around but rarely used, not promoted
- `in-progress/`: beta: public on purpose, feedback wanted, not shipped in the plugin
- `deprecated/`: no longer used

Every skill in `engineering/` or `productivity/` (the **promoted** buckets) must have a reference in the top-level `README.md` and an entry in `.claude-plugin/plugin.json`'s `skills` array (the Claude Code plugin ships exactly the promoted set). Skills in `misc/`, `in-progress/`, and `deprecated/` must not appear in either.

Install commands are copied verbatim from [.agents/install-block.md](./.agents/install-block.md). This repo is a fork and is not in the official Claude Code marketplace; `.claude-plugin/marketplace.json` makes it its own single-plugin marketplace, and that is the documented plugin route. Run `claude plugin validate . --strict` after touching either manifest. Why a Claude plugin but not (yet) a Codex one lives in [.agents/adr/0002-ship-as-a-claude-code-plugin.md](./.agents/adr/0002-ship-as-a-claude-code-plugin.md).

Each skill entry in the top-level `README.md` must link the skill name to its `SKILL.md`.

Each bucket folder has a `README.md` that lists every skill in the bucket with a one-line description, with the skill name linked to its `SKILL.md`. The promoted buckets' `README.md`s and the top-level `README.md` group entries into **User-invoked** and **Model-invoked**; non-promoted bucket `README.md`s (`misc/`, `in-progress/`) use a flat list.

Skills in `engineering/` and `productivity/` also have a human-facing docs page at `docs/<bucket>/<skill-name>.md` (the docs tree mirrors those two bucket folders under `skills/`). The pages are read on GitHub and link to each other with repo-relative paths (upstream publishes its copies at `https://aihero.dev/skills-<skill-name>`; this fork has no site). When you add, rename, or change the behaviour of a skill in `engineering/` or `productivity/`, create or re-sync its docs page following [.agents/writing-docs.md](./.agents/writing-docs.md). A finished page carries four sections: **What it does**, **When to reach for it**, **Common questions**, and **It's working if**. `writing-docs.md` holds the template, the section order, and where to hunt for the questions. Skills in the non-promoted buckets (`misc/`, `in-progress/`, `deprecated/`) get **no** docs page.

Every `SKILL.md` is either user-invoked (`disable-model-invocation: true` plus `policy.allow_implicit_invocation: false` in `agents/openai.yaml`, reachable only by the human) or model-invoked (model- or user-reachable). See [.agents/invocation.md](./.agents/invocation.md).

[`ask-matt`](./skills/engineering/ask-matt/SKILL.md) is the router that maps every user-reachable skill and how they relate. The same trigger that re-syncs a docs page applies to it: whenever you add, rename, remove, or change how a user-reachable skill fits the flows, re-read `ask-matt`'s `SKILL.md` and update it so the map stays accurate: a new skill it never mentions, or a stale one it still routes to, is a router that lies.

To (re)link every skill outside `deprecated/` and `misc/` into the local harness skill directories (`~/.claude/skills`, `~/.agents/skills`, `~/.pi/agent/skills`), run `scripts/link-skills.sh`. Each entry is a symlink into this repo, so a `git pull` keeps installed skills current; re-run the script after adding, removing, or renaming a skill.

Everything in this repo is written in **English**, apart from the literal conversation marker `喵！` and two translated-content exceptions: `README.zh-CN.md` is a translation of `README.md`, and `docs/engineering/poster/build_poster_zh.py` carries the Chinese strings rendered into the Chinese poster (`check-skills.mjs` allows CJK in exactly these paths). When `README.md` changes, change the translation in the same commit (same sections, same skill list, same links); skill names, commands and paths stay as they are. Skills never hard-code an output language. The user is answered in the language they write in: say "plain words" or "in the user's language", never "plain English". The `## Agent skills` block that `setup-matt-pocock-skills` writes carries the standing rule (replies in the user's language; written artefacts follow the project's existing docs language, else the user's; names, commands and paths unchanged), and the portable conversation block carries a minimal language reminder into every standalone install. Individual skills only restate the detailed artifact-language rule where they run before setup (`vibe`, `setup-matt-pocock-skills` itself) or produce a whole document for a human (`askcat`, `takeover`).

Every skill carries the portable conversation block from [.agents/conversation-style.md](./.agents/conversation-style.md): a warm, gentle, natural secretary-like manner and `喵！` at each conversational paragraph boundary, without altering technical artifacts or weakening gates. Use it when addressing the user in this repo too. Run `npm run sync-conversation-style` after changing the canonical block or adding a skill; it also updates the setup-generated project block and promoted docs notes. Root instructions alone are not shipped context, so never replace these local copies with a pointer an installed skill cannot resolve. The exact marker is the only additional CJK exception; other prose stays English.

`skills/engineering/vibe/ROUTES.md` must account for every promoted skill as kit, bring-back, or full-map. A new skill needs a route or an explicit reason it stays outside the curated kit, not just a plugin entry. The guide in `askcat` inventories actual files, deduplicates installed copies, and validates the generated cards against that inventory.

`npm run check-skills` (`scripts/check-skills.mjs`) checks the invariants above mechanically: every promoted skill in `README.md`, `README.zh-CN.md`, its bucket `README.md` and `plugin.json`; nothing non-promoted in any of them; a docs page with the fixed frame; `agents/openai.yaml` agreeing with the frontmatter on who may invoke; `ask-matt` naming every user-invoked skill; portable conversation blocks; complete Vibe route coverage; no em-dashes; no non-English text outside the translated paths and exact conversation marker. Run it before committing a change that adds, renames or removes a skill; it is the check the Shotgun-Surgery shape of that change needs.

`npm test` exercises policy synchronization, route coverage, and the actual Askcat renderer in a DOM, including clean commands, safe JSON insertion, picker paths, and progress. These checks also run in the Checks workflow and before release. Conversational behavior still needs the scenarios in [.agents/conversation-style-evals.md](./.agents/conversation-style-evals.md); static checks are not a substitute for a live agent run.

No em-dashes anywhere in this repo's prose (`SKILL.md` files, docs, `README.md`, `CHANGELOG.md`, ADRs, changesets, code comments). Where a sentence reaches for one, rewrite it instead with a comma, colon, period, parentheses, or a conjunction, whichever the sentence actually wants; never do a blind character substitution.
